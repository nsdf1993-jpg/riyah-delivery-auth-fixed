# رياح الجنوب للتوصيل السريع — Riyah Al-Janoub Delivery

تطبيق توصيل متكامل يربط الزبائن بالمندوبين والإدارة. مبني بـ React + TypeScript + Vite + Supabase.

## نظرة عامة

النظام يتكون من ثلاث واجهات:

| الواجهة | الوصف |
|---------|--------|
| **تطبيق الزبون** | إنشاء طلبات التوصيل، متابعة حالة الطلب، الاتصال بالمندوب، إلغاء الطلب، سجل الطلبات |
| **تطبيق المندوب** | استقبال الطلبات الجديدة، أخذ الطلب (مع منع التعارض)، تأكيد/توصيل/إلغاء، حالة الاشتراك |
| **لوحة الإدارة** | إدارة المندوبين والزبائن والطلبات، إيقاف/تفعيل المندوبين، تجديد الاشتراكات، إحصائيات |

## التقنيات

- **الواجهة**: React 18 + TypeScript + Vite + Tailwind CSS
- **الخريطة**: React Router للتنقل
- **الأيقونات**: Lucide React
- **الخط**: Tajawal / Cairo (عربي RTL)
- **الخادم/قاعدة البيانات**: Supabase (PostgreSQL + Auth + RLS + Edge Functions + Realtime)

> **ملاحظة عن Firebase**: طلب المشروع Firebase، لكن البيئة المتاحة توفر Supabase مُجهّزًا بالكامل. Supabase يوفّر نفس القدرات: مصادقة، قاعدة بيانات، قواعد أمان (RLS = Security Rules)، تحديثات لحظية، ودوال خادمية. لا يتطلب أي إعداد يدوي — كل شيء يعمل تلقائيًا.

## قاعدة البيانات

تم إنشاء الجداول التالية تلقائيًا عبر migrations:

| الجدول | الوصف |
|--------|--------|
| `profiles` | بيانات المستخدمين + الدور (زبون/مندوب/إدارة) |
| `drivers` | حالة المندوب + الاشتراك |
| `orders` | الطلبات بجميع الحالات |
| `subscriptions` | سجل اشتراكات المندوبين |
| `cancellations` | سجل أسباب الإلغاء |
| `notifications` | إشعارات داخلية |
| `settings` | إعدادات النظام (الأجرة، مدة الاشتراك) |

### الأمان (RLS)

- **الزبون**: يرى ويعدّل بياناته وطلباته فقط
- **المندوب**: يرى الطلبات الجديدة المتاحة + طلباته المسندة + بياناته
- **الإدارة**: صلاحيات كاملة
- لا توجد قواعد `allow all` — كل سياسة تحقق الملكية عبر `auth.uid()`

### منع التعارض عند أخذ الطلب

دالة `claim_order` الخادمية تستخدم `SELECT ... FOR UPDATE` ضمن معاملة ذرية لضمان أن مندوبًا واحدًا فقط يأخذ الطلب. إذا ضغط مندوبان في نفس اللحظة، ينجح الأول ويرى الثاني رسالة "الطلب تم أخذه من مندوب آخر".

### حالات الطلب

```
جديد → مأخوذ → مؤكد → بالطريق → تم التوصيل
                                            ↘ ملغي (في أي مرحلة قبل التسليم)
```

## التشغيل

```bash
npm install
npm run dev      # تشغيل بيئة التطوير
npm run build    # بناء للإنتاج
npm run typecheck # فحص الأنواع
```

متغيرات البيئة في `.env` (مُجهّزة مسبقًا):
- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`

## البدء السريع

1. افتح التطبيق → ستظهر صفحة تسجيل الدخول
2. بما أنه لا يوجد أدمن بعد، ستظهر زر **"إعداد حساب الإدارة الأول"**
3. أنشئ حساب الإدارة (سيُمنح دور admin تلقائيًا)
4. من لوحة الإدارة → **إدارة المندوبين** → **إضافة مندوب** (يُنشئ حساب مندوب + اشتراك 30 يوم تلقائيًا)
5. أنشئ حساب زبون من صفحة التسجيل
6. سجّل الدخول كزبون → أنشئ طلبًا → ستجده يظهر للمندوب المتاح

## ما هو جاهز تلقائيًا

- قاعدة البيانات (جداول، فهارس، علاقات)
- المصادقة (تسجيل/دخول/خروج، أدوار)
- قواعد الأمان (RLS على كل جدول)
- دوال خادمية (إنشاء طلب، أخذ الطلب، تحديث الحالة، الاشتراكات، إيقاف/تفعيل)
- دالة منع التعارض (claim_order)
- تحديث الحالة لحظيًا (Polling كل 5-6 ثوانٍ)
- الإشعارات الداخلية (تُحفظ في جدول notifications)
- إدارة المندوبين (إضافة/إيقاف/تفعيل/تمديد اشتراك)
- لوحة تحكم كاملة بالإحصائيات
- تصميم عربي RTL متجاوب

## ما يحتاج إعدادًا خارجيًا (اختياري)

### 1. Google Maps API (لعرض الخريطة والتتبع المباشر)
النظام حاليًا يستخدم إحداثيات GPS ويفتحها في خرائط Google. لدمج الخريطة داخل التطبيق:
1. احصل على مفتاح Google Maps JavaScript API من [Google Cloud Console](https://console.cloud.google.com/)
2. أضفه إلى `.env`: `VITE_GOOGLE_MAPS_API_KEY=your_key`
3. ثبّت `@react-google-maps/api` وادمجه في صفحات التتبع

### 2. Firebase Cloud Messaging (الإشعارات الفورية)
النظام يخزّن الإشعارات في قاعدة البيانات. لإرسال إشعارات فورية للجوال:
1. أنشئ مشروع Firebase وفعّل Cloud Messaging
2. احصل على Server Key و FCM tokens
3. أنشئ Edge Function لإرسال الإشعارات عبر FCM API

### 3. مفتاح Supabase Service Role (لإنشاء المندوبين)
مُجهّز تلقائيًا في البيئة. دالة `admin-create-driver` تستخدمه لإنشاء حسابات المندوبين.
